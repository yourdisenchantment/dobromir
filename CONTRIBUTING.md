# Правила участия

Проект небольшой: сайт одного центра, сопровождает один разработчик. Правки
принимаются, но сначала прочитайте этот файл - в репозитории есть правила, которые
нельзя нарушать даже случайно (данные о детях, ключи VK).

## Как предложить изменение

- **Нашли ошибку или есть идея** - создайте задачу (issue) в репозитории на GitVerse:
  что видите, где (адрес страницы, браузер, ширина экрана), что ожидали.
- **Готовы исправить сами** - запрос на слияние (pull request) в ветку `main`. Одна тема -
  один запрос.
- **Нашли уязвимость** - не в задачу, а по [SECURITY.md](SECURITY.md).
- Ответ на задачу или запрос - обычно в течение недели.

Ветка одна - `main`. Содержимое правится у себя и отправляется в GitVerse, сервер
забирает готовое оттуда; выкладывает разработчик.

## Где что лежит

- Правила работы и принятые решения - [AGENTS.md](AGENTS.md). Это главный документ:
  если что-то здесь с ним расходится, прав он.
- Поменять тексты, блоки главной, специалистов - [docs/HOWTO-add-content.md](docs/HOWTO-add-content.md)
  и документ раздела в [docs/content/](docs/content/) (без программирования).
- Поменять код: какой файл за что отвечает и что обновить рядом - [docs/HOWTO-change.md](docs/HOWTO-change.md).
- План, обоснования решений - [plan-razrabotki.md](plan-razrabotki.md); порядок работ -
  [docs/BACKLOG.md](docs/BACKLOG.md); открытые вопросы - [docs/OPEN-QUESTIONS.md](docs/OPEN-QUESTIONS.md).

## Подготовка

Нужны Node.js 24 (npm), Python 3.10 и [uv](https://docs.astral.sh/uv/).

```bash
(cd site && npm ci)               # сайт, из корня репозитория
(cd pipeline && uv sync)          # воркер
```

Хуки проверок ставятся один раз на машине, все три (из корня репозитория):

```bash
uv run --project pipeline pre-commit install
uv run --project pipeline pre-commit install --hook-type commit-msg
uv run --project pipeline pre-commit install --hook-type pre-push
```

Сайт без настоящих новостей запускается сразу: `cd site && npm run dev` (берется пример
`site/src/sample/news.example.json`).

## Требования к правке

- **Проверки проходят** (полный список - `AGENTS.md`, «Команды»):
  - `pipeline/`: `uv run ruff check src tests`, `uv run ruff format --check src tests`,
    `uv run mypy`, `uv run pytest`;
  - `site/`: `npm run lint`, `npm run format:check`, `npm run check`, `npm test`,
    `npm run build`.
  Хуки запускают их сами при коммите и отправке.
- **Новое поведение - с тестом.** Для воркера список обязательных случаев - `AGENTS.md`,
  «Воркер и сервер».
- **Изменилось поведение - обновлен документ**, который его описывает (колонка «Что еще
  обновить» в `docs/HOWTO-change.md`).
- **Язык:** комментарии, документы и сообщения коммитов - на русском; имена файлов,
  переменных и функций - на английском.
- **Версии зависимостей** не закрепляются руками, кроме TypeScript 6 - порядок и причины
  в `AGENTS.md`, «Ловушки».

## Коммиты

- Формат [Conventional Commits](https://www.conventionalcommits.org/ru/): `feat(site): ...`,
  `fix(pipeline): ...`, `docs: ...`. Тип - по-английски, текст - по-русски. Одна тема на
  коммит. Формат проверяет хук.
- Без строк `Co-Authored-By`, `Signed-off-by`, «Generated with ...» - хук такой коммит не
  пропустит.
- Перед коммитом посмотреть `git status`: в индексе не должно быть `.env`, базы, ответов
  VK и фото из группы.

## Чего нельзя

- **Ключи VK и другие секреты** - только в `~/dobromir-data/.env`, никогда в репозитории,
  примерах, тестах и логах.
- **Данные из группы VK** (ответы API, база, фото) - это материалы о детях. В репозиторий
  они не попадают. Для тестов - только обезличенные данные тестовой группы в
  `pipeline/tests/fixtures/`.
- **Фоновые процессы на хостинге** - Beget их запрещает; только короткий запуск из cron.
- **Загрузка чего-либо с чужих серверов** на сайте (шрифты, иконки, счетчики) - все лежит
  в проекте.

Участвуя в проекте, вы соглашаетесь с [кодексом поведения](CODE_OF_CONDUCT.md).
