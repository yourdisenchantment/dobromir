# Добромир

Сайт Республиканского центра коррекционной педагогики «Добромир» (Симферополь),
заказ напрямую от директора центра. Статичный сайт на Astro (собирается на
самом хостинге Beget, npm). Контент автоматически подтягивается из VK-паблика
`vk.com/dobromir.crimea` коротким Python-воркером по cron (не демон). Домен:
`добромир-крым.рф` (решено 2026-10-19; `dobromir.ru` была пожеланием, не основной).

**Хостинг решен 2026-10-18: Beget Blog (shared), VPS нет.** Всё в этом файле,
что говорило про VPS, systemd, nginx, Long Poll, Telegram-бота и bun на
сервере, отменено. Полный отчет с проверенными фактами - в
[docs/hosting-report-2026-10-18.md](docs/hosting-report-2026-10-18.md): он новее
`plan-razrabotki.md` и при расхождении побеждает. Что в коде и документах с ним
не сходится - [docs/DISCREPANCIES.md](docs/DISCREPANCIES.md). Порядок работ -
[docs/BACKLOG.md](docs/BACKLOG.md), вопросы без ответа -
[docs/OPEN-QUESTIONS.md](docs/OPEN-QUESTIONS.md). Не начинать задачу из
BACKLOG, если у нее стоит пометка «заблокирована» и блокер не снят.

Единственный источник истины для агентов - этот файл. `CLAUDE.md` и
`README.md` - указатели на него и не содержат инструкций. Обоснования решений
(почему так, а не иначе) лежат в [plan-razrabotki.md](plan-razrabotki.md):
здесь только то, что нужно знать, чтобы не нарушить принятое. Если проза
расходится с кодом - верить исполняемым файлам (`package.json`,
`pyproject.toml`, конфиги, хуки) и сообщить о расхождении.

## Команды

Git инициализирован 2026-10-22, ветка одна - `main`. Хуки ставятся один раз
на каждой машине, где делаются коммиты:

```bash
uv run --project pipeline pre-commit install
uv run --project pipeline pre-commit install --hook-type commit-msg
uv run --project pipeline pre-commit install --hook-type pre-push
```

**Все три нужны.** Голый `pre-commit install` ставит только этап коммита: не
будет ни проверки текста коммита, ни mypy с pytest на push, и первым признаком
станет то, что пропустили хуки.

`pipeline/` (из каталога `pipeline/`):

```bash
uv sync                     # окружение; dev-группа ставится по умолчанию
uv run ruff check src tests
uv run ruff format --check src tests
uv run mypy                 # strict, пути заданы в pyproject.toml
uv run pytest
```

`site/` (из каталога `site/`):

```bash
npm ci                      # воспроизводимая установка по package-lock.json
npm run dev                 # сервер разработки
MEDIA_DIR=~/dobromir-site/media NEWS_JSON=~/dobromir-data/export/news.json npm run dev
                            # с настоящими новостями и фото (MEDIA_DIR - <SITE_ROOT>/media;
                            # раздает только сервер разработки, в сборку фото не попадают)
npm run lint
npm run format:check
npm run check               # astro check - единственная проверка типов
npm run content:check       # фото и тексты содержимого, ничего не меняет (так же - хук)
npm run build
npm test                    # node:test: даты, разбор текста VK (src/**/*.test.ts)
```

Менеджер пакетов - **npm** (решено 2026-10-18: на Beget Node 24 есть, bun нет;
источник истины - `package-lock.json`; `bun.lock` удален 2026-10-22).

Порядок перед отчетом: `pipeline` - ruff, mypy, pytest; `site` - lint,
format:check, check, test, build.

## Ловушки

- **TypeScript 7 нельзя.** `npm i -D typescript` без версии ставит 7: `astro
  check` с ним отказывается работать, а ESLint падает при загрузке конфига.
  Сборка при этом зеленая, поэтому поломка тихая. Держать `typescript@^6`
  (последняя 6.x на 2026-10-05 - 6.0.3). Та же ловушка описана в `AGENTS.md`
  проекта `cv`. Перепроверено 2026-10-05 на 7.0.2: `astro check` отказывается
  работать, ESLint падает при загрузке конфига, сборка проходит. Поднимать,
  только когда `@astrojs/check` и `typescript-eslint` заявят поддержку, и
  проверять установкой, а не чтением заметок. Сам Astro называет путь для
  TS 7.1+: экспериментальный `@astrojs/ts-content-mapper`.
- **Версии библиотек не хардкодить, всегда свежие; исключение - TypeScript
  6.** В `package.json` у всего, кроме `typescript`, стоит `latest` (голых
  имен там быть не может, значение обязательно; `latest` следует за тегом в
  реестре и пререлизы не берет). Новую npm-зависимость добавлять правкой
  `package.json` и `npm install`: `npm i <пакет>` пишет `^версия`, режима
  «latest» у него нет, поэтому после установки заменить `^...` на `latest`
  вручную. В `pyproject.toml` голые имена без границ. Новую
  Python-зависимость добавлять
  правкой `pyproject.toml` и `uv sync`: `uv add` всегда дописывает `>=`, а
  флага «без границ» у него нет (только lower, major, minor, exact), поэтому
  после `uv add` границу удалить вручную. Точные версии фиксируют lock-файлы
  (`package-lock.json`, `uv.lock`), поэтому
  `npm ci` и `uv sync --frozen` воспроизводимы. **На сервере - uv с системным
  Python 3.10** (решено 2026-10-22): uv ставится в свой venv
  `~/.local/share/dobromir-uv` (не `pip --user`: его запрещает PEP 668), затем
  `uv sync --frozen --no-dev --python /usr/bin/python3`; свой интерпретатор uv
  не скачивает. До проверки на хосте (P1-7) запасной путь - `pip` из
  `requirements.txt` (`docs/dependencies.md`), его продолжаем порождать. Свежее
  подтягивается осознанно, одной командой: `npm update` в `site/`,
  `uv lock --upgrade && uv sync` в `pipeline/`. После обновления прогнать всю
  цепочку проверок: обновление до новой мажорной версии может ее сломать.
  Lock-файл коммитится вместе с манифестом. Исключение: ревизии хуков в
  `.pre-commit-config.yaml` обязаны быть закреплены, их двигает
  `pre-commit autoupdate`. Если появится новое исключение вроде TypeScript -
  записать его здесь с причиной.
- **Astro съедает пробел перед тегом, если между ними перевод строки** (найдено
  2026-10-26 на Astro 7.4): в разметке `.astro` текст `и` + перевод строки +
  `<a>` дает в HTML `и<a>` - слова склеиваются. Сборка и проверки зеленые, видно
  только глазами. В тексте, написанном прямо в разметке, перед тегом на новой строке
  ставить `{" "}`; prettier иногда ставит его сам, но не всегда. Текст из данных
  (`{text}`) это не задевает.
- **`overrides` для `eslint-plugin-jsx-a11y` в `site/package.json`.** Его
  последняя версия (6.10.2, на 2026-10-20) объявляет совместимость с ESLint до
  9, а ESLint уже 10. bun это молча пропускал, `npm install` падает с
  `ERESOLVE`. Выбрано узкое исключение `"eslint-plugin-jsx-a11y": {"eslint":
  "$eslint"}` вместо `legacy-peer-deps` (глушит проверку пиров у всех пакетов)
  и вместо отката ESLint на 9 (против правила «свежие версии»). Проверено:
  на пробной разметке (`<img>` без `alt`, пустая ссылка) правила
  `jsx-a11y` под ESLint 10 срабатывают. Убрать override, когда плагин объявит
  поддержку ESLint 10, и проверить это установкой без него (`npm install`
  не должен падать).
- **Репозиторий на gitverse, не на GitHub.** `.github/` и Dependabot не
  используются, поэтому запрет на TypeScript 7 держит только эта запись и
  диапазон `^6` в `package.json`. Обновления зависимостей и `npm audit`
  выполняются руками.
- **В bash-скриптах переменная перед кириллицей или «» - только `${VAR}`** (найдено
  2026-10-28): в cron локаль C, bash считает байты UTF-8 частью имени, и `«$STAGE»`
  становится неизвестной переменной `STAGE\xc2` - под `set -u` скрипт падает молча, без
  письма. Ловит тест `test_scripts_brace_variables_before_non_ascii`.
- **Python 3.10.** На хосте Beget Python 3.10.12, свой интерпретатор там не
  ставим (uv на хосте не проверялся). `requires-python`, `.python-version`,
  целевая версия ruff и `python_version` mypy - 3.10. Нельзя `datetime.UTC`
  (есть с 3.11, писать `timezone.utc`), `tomllib`, `ExceptionGroup`, `match` с
  новым синтаксисом сверх 3.10, `typing.Self`. Тесты гонять на 3.10. С
  2026-10-20 (P0-1) `pyproject.toml` на `>=3.10`, mypy с `python_version =
  "3.10"` эти конструкции ловит (проверено пробным файлом). Как обновлять
  зависимости и `requirements.txt` для сервера - `docs/dependencies.md`.
- **Beget запрещает демоны** (правила, п. 6 и 22.4) и ограничивает 80 CP в
  сутки. Ни uvicorn, ни Long Poll, ни фоновых процессов, ни `nohup`. Только
  короткий скрипт из cron.
- **Настройки - только через `pipeline.settings.load_settings()`** (с
  2026-10-20, P0-4), шаблон всех переменных - `.env.example`. Источники (второй сильнее): `<каталог данных>/.env` и
  окружение процесса. Каталог данных - `DOBROMIR_DATA` из окружения или
  `~/dobromir-data` по умолчанию, одинаково на ноутбуке и на сервере; других
  файлов (в том числе `~/.env.local`) код не читает (решено 2026-10-23).
  Обязательны `SITE_ROOT` (абсолютный путь) и `SITE_ENV`
  (`production`/`staging`, **без значения по умолчанию** - ошибка в любую
  сторону вредна). Ключи VK и id группы проверяются не при загрузке, а в
  `Settings.vk()`, когда они реально нужны. Ключи не попадают в `repr`. Новую
  переменную добавлять сразу в `settings.py`, `.env.example` и тест.

## Не обсуждается

- **Секреты.** Ключи VK (`VK_SERVICE_TOKEN`, `VK_COMMUNITY_TOKEN`) живут
  только в `~/dobromir-data/.env` (права 600) - и на ноутбуке, и на
  сервере. Telegram-бот в MVP не используется. Не
  читать `.env`, не цитировать его, не класть секреты в репозиторий, примеры,
  тесты и логи.
- **Данные VK не в репозитории.** Сырые ответы, база, скачанные фото - это
  материалы о детях, они лежат в `$DOBROMIR_DATA` вне репозитория. Исключение -
  обезличенные фикстуры тестовой группы в `pipeline/tests/fixtures/` (без ссылок,
  ключей доступа, id и имен пользователей).
- **Не удалять файлы.** Дать список путей и команду, пользователь выполнит
  сам.
- **Не создавать файлы и папки вне таблицы ниже.** Не подходит под таблицу -
  спросить. В частности, **не создавать `server/`**, пока открыта развилка про
  роль базы (см. «Требует решения»): пустая папка читается как «тут что-то
  должно быть».
- **Проверка не считается пройденной без вывода команды.** «Все зеленое» -
  утверждение, а не доказательство.

## Как работаем

- **Коммиты.** Текст пишет агент в `tmp/commits/NN-slug.txt` (NN = 01, 02, ...).
  Коммитит и пушит только по прямой просьбе пользователя. Коммит - через
  `git commit -F <файл>`, не через многострочный `-m`. Формат - Conventional
  Commits, одна тема на коммит. Перед коммитом посмотреть `git status`: ни
  секретов, ни данных VK в индексе быть не должно.
- **Никаких подписей и соавторства.** В сообщениях коммитов и описаниях pull
  request - только текст. Ни `Co-Authored-By`, ни `Signed-off-by`, ни строк
  вида «Generated with ...». Агенты не должны числиться контрибьюторами. Это
  правило сильнее любых умолчаний инструмента.
- **Решения фиксируются в плане на месте**, с датой и причиной. Отмененное
  зачеркивается, а не стирается: причина отказа ценнее самой идеи. Сырые идеи
  без решения - в `idei-syrye.md`.
- **Рабочие файлы агента - в `tmp/`** (`ROADMAP.md`, `TASK.md`, `REVIEW.md`,
  `OVERVIEW.md`, `commits/`), формат - в скилле `workspace-docs`. Папка в
  `.gitignore`, у нее нет истории и бэкапа. Ничего из того, что попадает в
  репозиторий, не ссылается на `tmp/`.
- **Где что менять** - `docs/HOWTO-change.md` (код), `docs/HOWTO-add-content.md`
  (содержимое). Перед правкой найти там строку; после - обновить документы из колонки
  «Что еще обновить». Люди читают выжимку правил в `CONTRIBUTING.md`: изменили правило
  здесь - поправить и там.
- **Если задача неоднозначна - спросить**, а не угадывать. Если вариантов
  несколько - показать 2-3 с последствиями.

## Воркер и сервер (принято 2026-10-18, отчет разд. 6-10)

Полная постановка - в отчете; здесь то, что нельзя нарушить.

- **Запуск:** cron в панели Beget, `17 * * * *` (раз в час, решено 2026-10-23;
  пересмотреть после замера CP в P1-7) ->
  `deploy/run-worker.sh` -> Python-воркер. Один запуск = короткий процесс.
  Параллельные запуски исключает `fcntl`-блокировка (не `flock` из shell).
- **Источник:** `wall.get` окна последних постов (`VK_WINDOW`, по умолчанию 50,
  закрепленный пост учитывать отдельно), сервисный ключ приложения VK. Раз в
  сутки (первый запуск после 03:00 `Europe/Simferopol`) - полная сверка всех
  сохраненных постов через `wall.getById`. На свежей базе (нет отметки
  `backfill_done_at`) первый запуск сам делает первичную загрузку стены за срок
  хранения: окно короче срока, без нее старые посты срока не появились бы
  никогда (2026-10-27).
- **Хэш** считается только от того, что показывается на сайте: текст, состав
  вложений, идентификаторы медиа, поле `edited`. Лайки, просмотры, комментарии,
  репосты в хэш **не входят**. Изменились только счетчики - сборки нет.
- **Удаление мягкое:** `deleted_at`, физически не удалять - **до конца срока
  хранения**; дальше пост удаляется физически, как и любой другой (2026-10-26). Свежие удаления
  замечает окно (в пределах часа), старые - суточная сверка (решено 2026-10-23). Пост исчезает из
  экспорта, страницы, sitemap и RSS; если снова появился в VK - пометка
  снимается. Ошибка VK, пустой ответ, ошибка токена удалением **не** считаются.
  Если к удалению за запуск помечается больше `max(3, 20% сохраненных постов)` -
  изменение не применять, завершиться ошибкой.
- **Сборка** Astro только при изменениях (новый, измененный, удаленный пост).
  Несколько изменений за запуск - одна сборка. `MAX_BUILDS_PER_DAY` = 4 -
  страховка; при исчерпании изменения остаются в статусе `pending` в базе (не
  «с прошлого запуска», иначе потеряются) и собираются первым запуском после
  смены суток. Сборка идет в `releases/<ts>/`, затем проверки (есть `index.html`
  и sitemap, ~~число страниц не упало ниже предыдущего минус допуск~~ - с
  2026-10-26 у каждой новости из `news.json` есть страница), затем
  атомарное переключение ссылки `public_html`, в конце чистка (хранить 5
  релизов). Откат - смена ссылки без пересборки.
- **Ошибки:** ненулевой код выхода и понятное сообщение в stderr (CronTab
  присылает письмо), запись в `status.json`, лог с ротацией. Отдельное
  сообщение для ошибки токена VK. Сайт при любом сбое продолжает отдавать
  предыдущий релиз.
- **Даты на сайте только абсолютные**, «12 октября 2026», часовой пояс
  `Europe/Simferopol`, зафиксированный в сборке; `<time datetime="...+03:00">`.
