# Как менять содержимое сайта

Для кого: человек, который правит сайт сам или вместе с нейросетью (решение В9,
2026-10-19). Писать код не нужно: все, что видно на главной, кроме новостей, лежит в
JSON-файлах в `site/content/`. Новости приходят из группы VK сами (воркер на сервере,
раз в час), их здесь не правят.

Если работаете с нейросетью - дайте ей этот файл и документ нужного раздела и
попросите действовать строго по ним. Подсказка для нее - в конце этого файла и в конце
каждого документа раздела.

| Услуги | `services/` | [content/services.md](content/services.md) |

В каждом документе: где раздел виден на сайте, таблица полей, рецепты «изменить»,
«добавить», «убрать», «переставить», частые ошибки и подсказка для нейросети.

**Не трогать:** все, что вне `site/content/`; поле `type` у раздела (вид раздела меняет
разработчик); `slug` у специалиста после публикации.

## Как править

1. **Править у себя**, на своем компьютере, в клоне репозитория. На сервере ничего не
   правится: он только забирает готовое из GitVerse.
2. **Открыть `block.json` нужного раздела** и поменять текст в кавычках по документу
   раздела. Фото - положить в папку `photos/` раздела (сейчас фото есть только у
   специалистов).
3. **Собрать** из папки `site/`:

   ```bash
   npm run build
   ```

4. **Посмотреть глазами** - сервер разработки, страница http://localhost:4321/
   обновляется при каждом сохранении файла:

   ```bash
   npm run dev
   ```

5. **Отправить в GitVerse** (`git add`, `git commit`, `git push`; правила текста
   коммита - `CONTRIBUTING.md`). Как сайт на сервере забирает новую версию - отдельная
   инструкция, готовится вместе с серверными скриптами (BACKLOG, P1-7); до тех пор
   выкладывает разработчик.

## Что сборка делает сама

`npm run build` у вас на компьютере сначала доводит содержимое
(`site/scripts/prepare-content.ts`), потом проверяет и собирает сайт:

- **Фото.** Если в `photo` указан JPEG или PNG, сборка поворачивает его, как снимали,
  уменьшает до 800 px, сохраняет WebP без метаданных (геометки, модель телефона) и
  вписывает новое имя в `block.json`. Исходник в git не попадает.
- **Текст.** Убирает лишние пробелы, ставит тире вместо дефиса между словами (« - » ->
  « — », «- пункт» -> «— пункт»), меняет парные прямые кавычки на «елочки». Ссылки,
  телефоны, имена файлов и `slug` не трогает.
- Что исправила, сборка перечисляет: «Содержимое доведено: ...». Посмотрите, все ли так.

**На сервере** и при коммите (хук) сборка ничего не меняет, только проверяет. Если
фото не обработано или текст не доведен, она остановится и скажет «запустите npm run
build у себя» - сайт при этом продолжит показывать прежнюю версию.

Проверить содержимое без сборки сайта (быстро, ничего не меняет):

```bash
npm run content:check
```

## Ошибки

Если в содержимом ошибка, сборка остановится и скажет по-русски, какой файл и какое
поле:

```txt
Ошибка в site/content/blocks/facts/block.json:
  - items.1.label: label (подпись): пусто
```

`items.1` - вторая запись списка `items` (счет с нуля). Исправить и собрать снова.
Сломанный сайт с ошибкой не выйдет: сборка просто не пройдет.

## Правила JSON, которые чаще всего нарушают

- Текст - в прямых кавычках `"..."`. Кавычки **внутри** текста - «елочки». Прямую кавычку
  внутри текста можно только как `\"` (сборка сама заменит `\"...\"` на «...»); просто `"`
  ломает файл.
- Между записями списка и между полями - запятая; после последней - нет.
- Число без кавычек (`"count": 12`), цифра для показа - в кавычках (`"value": "250+"`).
- Удалили запись - проверьте запятые до и после нее.

Ошибка такого рода выглядит как «JSON не читается» с номером строки.

## Подсказка для нейросети

> Правь только файлы в `site/content/` по `docs/HOWTO-add-content.md` и документу раздела
> из `docs/content/`. Не меняй поле `type`, не трогай файлы вне `site/content/`, не
> придумывай новых полей - их нет в таблицах, и сборка их не пропустит. Тексты - на
> русском, кавычки «елочки», тире «—». Фото не конвертируй сам: положи файл в `photos/`
> и впиши имя в `photo` - это доделает `npm run build`. После правки запусти
> `npm run build` в `site/` и, если есть ошибка, исправь по ее тексту. Ничего не удаляй
> сам: дай список файлов и команду.
