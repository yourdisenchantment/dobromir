# Как менять содержимое сайта

Для кого: человек, который правит сайт вместе с нейросетью (решение В9, 2026-10-19).
Писать код не нужно: все, что видно на главной, кроме новостей, лежит в JSON-файлах.
Новости приходят из группы VK сами (воркер, раз в час), их здесь не правят.

Если работаете с нейросетью - дайте ей этот файл целиком и попросите действовать
строго по нему. Подсказка для нее - в конце.

## Где что лежит

```txt
site/content/
    page.json                     порядок блоков на главной
    blocks/
        hero/block.json           первый экран
        center/block.json         «О центре»
        news/block.json           новости (только заголовок и сколько показать)
        services/block.json       услуги
        directions/block.json     направления
        facts/block.json          цифры
        specialists/block.json    специалисты
        specialists/photos/       их фото (WebP)
        about/block.json          «О нас»
        reviews/block.json        отзывы
        contacts/block.json       контакты: адрес и телефоны для всего сайта
```

Одна папка - один блок на главной. Имя папки - адрес блока: блок `services`
открывается по ссылке `/#services`. Имя - латиницей, маленькими буквами, можно цифры и
дефис.

**Не трогать:** все, что вне `site/content/`; поле `type` у существующего блока (тип
меняет разработчик); `slug` у специалиста, на которого уже могли дать ссылку (его
адрес - `/specialisty/<slug>/`).

## Как проверить себя

Из папки `site/`:

```bash
npm run build
```

Если в содержимом ошибка, сборка остановится и скажет по-русски, какой файл и какое
поле. Например:

```txt
Ошибка в site/content/blocks/facts/block.json:
  - items.1.label: label (подпись): пусто
```

`items.1` - вторая запись списка `items` (счет с нуля). Исправить и собрать снова.
Сломанный сайт с такой ошибкой не выйдет: сборка просто не пройдет.

Посмотреть глазами - сервер разработки, страница http://localhost:4321/ обновляется
при каждом сохранении файла:

```bash
npm run dev
```

С настоящими новостями и фото - команда из `AGENTS.md`, раздел «Команды».

## Как опубликовать

1. Проверить: `npm run build` в `site/` проходит.
2. Коммит и отправка в репозиторий (`git commit`, `git push`), правила текста коммита -
   `AGENTS.md`.
3. Метка релиза: `git tag v0.3.0 && git push origin v0.3.0` (номер - следующий после
   последнего, `git tag` покажет).
4. На сервере: `./deploy/deploy.sh v0.3.0 --switch` из клона `~/dobromir`. Скрипт
   соберет сайт, проверит его и включит; старая версия остается, откат - командой,
   которую скрипт печатает.

## Рецепты

### Поправить текст

Найти блок по таблице выше, поменять текст в кавычках, сохранить, проверить. Кавычки
внутри текста - «елочки», не `"`: прямая кавычка ломает JSON.

### Переставить блоки или убрать блок с главной

`page.json` - список имен папок сверху вниз:

```json
{
    "blocks": ["hero", "center", "news", "services", "directions", "facts", "specialists", "about", "reviews", "contacts"]
}
```

Переставить имена - блоки переедут. Убрать имя - блок пропадет с главной, папку можно
оставить. Меню в шапке идет в том же порядке само. Блок `contacts` убирать нельзя:
из него шапка и подвал берут телефон.

### Пункт меню

У блока поле `"menu": "Услуги"` - блок есть в меню с этой надписью (до 20 знаков).
Нет поля - нет пункта. Пунктов лучше не больше пяти-шести: шапка в одну строку.

### Добавить блок

1. Скопировать папку похожего блока под новым именем, например `blocks/prices/`.
2. Поправить `block.json` по справочнику ниже.
3. Вписать имя в `page.json` в нужное место.

Блок нового вида (таблица, видео, форма) - это новый тип, его добавляет разработчик.

### Сменить телефон или адрес

Только в `blocks/contacts/block.json`. Первый телефон в `phones` - телефон для записи:
он же в шапке, в подвале и на страницах специалистов.

### Добавить специалиста

1. Фото: портрет, лицо в верхней трети. Перевести в WebP не больше 800 px и без
   метаданных (из корня репозитория, пути - свои):

   ```bash
   uv run --project pipeline python -c "from PIL import Image, ImageOps; im = ImageOps.exif_transpose(Image.open('ivanova.jpg')).convert('RGB'); im.thumbnail((800, 800)); im.save('site/content/blocks/specialists/photos/ivanova.webp', quality=82)"
   ```

2. В `blocks/specialists/block.json` в список `items` добавить запись (место в списке -
   место в карусели):

   ```json
   {
       "slug": "ivanova",
       "name": "Иванова Анна Сергеевна",
       "position": "Логопед-дефектолог",
       "short": "Запуск речи, постановка звуков",
       "photo": "ivanova.webp",
       "description": [
           "Первый абзац о специалисте.",
           "Направления работы:",
           "— запуск речи;",
           "— постановка звуков."
       ]
   }
   ```

   `slug` - фамилия латиницей, у каждого свой; из него адрес `/specialisty/ivanova/`.
   Строки, которые начинаются с «— », складываются в список.

Убрать специалиста - удалить его запись из `items`; фото удалить отдельной командой.

### Добавить услугу

В `blocks/services/block.json` в `items`:

```json
{ "title": "Сенсорная интеграция", "text": "Короткое описание в два-три предложения." }
```

## Справочник: типы блоков

Обязательные поля - без пометки, необязательные - «можно не писать». У любого блока
можно `"menu"` (см. выше).

**`hero`** - первый экран. `title` - главный заголовок страницы; `lead` (можно не
писать); `actions` - до двух кнопок, первая основная:

```json
{
    "type": "hero",
    "title": "Мир не делится на черное и белое",
    "lead": "Подзаголовок одной-двумя фразами.",
    "actions": [
        { "label": "Записаться по телефону", "href": "tel:+79782294854" },
        { "label": "Услуги центра", "href": "#services" }
    ]
}
```

**`text`** - заголовок и абзацы; `quote` - цитата над текстом (можно не писать).
Первый абзац крупнее; строки «— ...» - список:

```json
{
    "type": "text",
    "title": "О нас",
    "quote": { "text": "Текст цитаты.", "author": "Автор" },
    "paragraphs": ["Абзац.", "Руководство:", "— первый пункт", "— второй пункт"]
}
```

**`cards`** - карточки в карусели. У карточки обязателен только `title`; `subtitle`,
`text`, `list` (пункты) - можно не писать. `intro` - абзац над каруселью:

```json
{
    "type": "cards",
    "title": "Направления",
    "items": [
        { "title": "Движение", "list": ["Адаптивная физкультура", "Массаж"] },
        { "title": "Сурдологопедия", "text": "Описание." }
    ]
}
```

**`facts`** - цифры, лучше четыре. `source` - если цифра чужая, указать откуда:

```json
{
    "type": "facts",
    "title": "Центр в цифрах",
    "items": [
        { "value": "250+", "label": "детей занимаются в центре" },
        { "value": "1500", "label": "детей с аутизмом в Крыму", "source": { "title": "Минздрав РК, 2024", "url": "https://..." } }
    ]
}
```

**`news`** - последние новости из VK. `count` - сколько карточек (по умолчанию 12, не
больше 30):

```json
{ "type": "news", "menu": "Новости", "title": "Новости", "count": 12 }
```

**`specialists`** - только в папке `specialists`, поля карточки - в рецепте выше;
`intro` - абзац над каруселью (можно не писать).

**`quotes`** - отзывы. `author` можно не писать, тогда подпись «Отзыв родителей».
Имен детей в отзывах не оставлять:

```json
{
    "type": "quotes",
    "title": "Что говорят родители",
    "items": [{ "text": "Текст отзыва.", "author": "Мама воспитанницы" }]
}
```

**`contacts`** - адрес, как добраться, ссылка на карту, телефоны, группа VK. Блок
обязателен (см. «Сменить телефон»):

```json
{
    "type": "contacts",
    "title": "Контакты",
    "address": "Симферополь, ул. Желябова, 44",
    "text": "Как добраться и где оставить машину.",
    "map": "https://yandex.ru/maps/?text=Симферополь, улица Желябова, 44",
    "phones": [
        { "label": "Запись — только по телефону", "number": "+7 978 229-48-54" },
        { "label": "Общий телефон", "number": "+7 978 799-17-09" }
    ],
    "vk": "https://vk.com/dobromir.crimea"
}
```

## Подсказка для нейросети

> Правь только файлы в `site/content/` по `docs/HOWTO-add-content.md`. Не меняй поле
> `type`, не трогай файлы вне `site/content/`, не придумывай новых полей - их нет в
> справочнике, и сборка их не пропустит или молча проигнорирует. Тексты - на русском,
> кавычки «елочки», тире «—». После правки запусти `npm run build` в `site/` и, если
> есть ошибка, исправь по ее тексту. Ничего не удаляй сам: дай список файлов и команду.
