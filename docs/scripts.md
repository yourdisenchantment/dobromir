# Скрипты проекта

Для кого: разработчик и нейросеть. Описывает скрипты, которые запускаются при сборке
и проверке содержимого сайта.

## site/scripts/prepare-content.ts

**Что делает:** доводит ручное содержимое (`site/content/`) до готового вида перед сборкой.

**Запуск:**
- `npm run build` (в `site/`) — вызывает скрипт автоматически первым шагом
- `npm run content:check` — только проверка, ничего не меняет
- `CONTENT_CHECK_ONLY=1 npm run build` — то же самое (для сервера и хуков)

**Что делает с фото (только specialists/photos/):**
1. Находит все `block.json` с полем `photo` у элементов `items`
2. Для каждого фото проверяет, готово ли оно:
   - WebP формат
   - Длинная сторона <= 800 px
   - Нет EXIF, XMP, IPTC (метаданных)
3. Если не готово — конвертирует:
   - Поворот по EXIF (ориентация)
   - Уменьшение до 800 px по длинной стороне (без увеличения)
   - WebP, quality 82
   - Метаданные не переносятся (sharp по умолчанию их не пишет)
4. Вписывает новое имя в `block.json` (например `ivanova.jpg` -> `ivanova.webp`)
5. Исходник остается в папке, но в git не попадает (.gitignore)

**Что делает с текстом:**
- Убирает лишние пробелы
- Ставит тире «—» вместо дефиса между словами (« - » -> « — »)
- Меняет парные прямые кавычки на «елочки»
- Ссылки, телефоны, имена файлов и `slug` не трогает
- Полный список правил — `site/src/lib/typography.ts`

**Что проверяет дополнительно:**
- Неиспользуемые фото в папке `photos/` — предупреждение в логе
- HEIC формат — ошибка с подсказкой (сохраните как JPEG)
- Нечитаемые файлы — ошибка

**Режим проверки (--check / CONTENT_CHECK_ONLY=1):**
- Ничего не меняет
- Если фото не обработано или текст не доведен — ошибка с сообщением «запустите npm run build у себя»
- Используется на сервере и в pre-commit хуке

**Поддерживаемые форматы фото:** `.jpg`, `.jpeg`, `.png`, `.tif`, `.tiff`, `.gif`, `.avif`, `.heic`, `.heif`

## site/src/lib/typography.ts

**Что делает:** функция `fixTexts()` — рекурсивно обходит JSON и применяет правила типографики к строкам.

**Правила (в порядке применения):**
1. Лишние пробелы -> один пробел
2. Дефис между словами -> тире «—» (« - » -> « — », «- пункт» -> «— пункт»)
3. Парные прямые кавычки -> «елочки» («...» -> «...»)
4. Ссылки, телефоны, имена файлов, `slug` — не трогаются

**Что не трогает:**
- `slug` (адреса страниц)
- `photo` (имена файлов)
- `href` (ссылки)
- Поля с URL, телефонами, датами

## pipeline/ (Python-скрипты)

**Команды** (запускаются из `pipeline/` через `uv run python -m pipeline <команда>`):

| Команда | Что делает |
|---------|-----------|
| `survey` | Разведка стены VK (только чтение) |
| `import` | Импорт постов из VK в базу |
| `photos` | Скачать фото живых постов |
| `export` | Записать `news.json` из базы |
| `backfill` | Первичная загрузка: посты за срок хранения |
| `sync` | Один проход: окно VK, сверка, фото, news.json |
| `sync --full` | То же + принудительная полная сверка |
| `worker` | Запуск из cron: блокировка, синк, сборка, status.json |
| `rollback` | Вернуть public_html на предыдущий релиз |
| `build` | Пробная сборка в releases/ |
| `migrate` | Применить миграции базы |
| `backup` | Бэкап SQLite |
| `media-cleanup` | Чистка неиспользуемых фото |
| `media-cleanup --dry-run` | Показать, что будет удалено |

**Настройки:** только через `pipeline.settings.load_settings()`. Источники: `<каталог данных>/.env` + окружение процесса.

## deploy/ (серверные скрипты)

| Скрипт | Что делает |
|--------|-----------|
| `bootstrap.sh` | Первичная подготовка (без `--apply` только проверяет) |
| `deploy.sh` | Обновление из main (руками или `--cron`) |
| `run-worker.sh` | Для cron: запуск воркера с правильным окружением |
| `backup-db.sh` | Бэкап SQLite (7 копий) |
| `locked.py` | Запуск под блокировкой воркера |

## Порядок запуска при правке содержимого

1. Открыть `block.json` нужного раздела
2. Поменять текст/добавить карточку/убрать запись
3. Если добавляете фото специалиста — положить файл в `photos/` (JPEG/PNG/любой формат)
4. Запустить `npm run build` в `site/` — скрипт обработает фото и тексты, проверит схему, соберет сайт
5. Посмотреть результат: `npm run dev` -> http://localhost:4321/
6. Отправить в GitVerse: `git add`, `git commit`, `git push`

## Что сборка делает сама

| Что | Как |
|-----|-----|
| Фото | Поворот, уменьшение до 800 px, WebP без метаданных, имя в block.json |
| Текст | Лишние пробелы, тире, кавычки «елочки» |
| Проверка | Схема zod: типы, обязательные поля, наличие файлов фото |
| Ошибки | По-русски, с указанием файла и поля |

## Что сборка НЕ делает

- Не меняет `type` блока
- Не добавляет новые поля (они не пройдут схему)
- Не удаляет файлы (только предупреждает о неиспользуемых)
- На сервере/в хуке: только проверка, не меняет файлы
