# Специалисты (`specialists`)

**Где на сайте:** главная, карусель «Специалисты»: фото, имя, должность, «кратко».
Карточка открывается окном с полным описанием; у каждого специалиста есть и своя
страница `/specialisty/<slug>/` (на ней же кнопка записи с телефоном из контактов).
**Файлы:** `site/content/blocks/specialists/block.json` и фото в
`site/content/blocks/specialists/photos/`.

Общие правила - в [HOWTO-add-content.md](../HOWTO-add-content.md).

## Поля

Блок:

| Поле | Обязательно | Что это |
|---|---|---|
| `type` | да | всегда `"specialists"`, блок лежит только в папке `specialists` |
| `menu` | нет | пункт меню в шапке, до 20 знаков |
| `title` | да | заголовок раздела |
| `intro` | нет | абзац под заголовком |
| `items` | да | специалисты, хотя бы один; порядок - порядок в карусели |

Специалист (запись в `items`):

| Поле | Обязательно | Что это | Ограничения |
|---|---|---|---|
| `slug` | да | адрес страницы: `/specialisty/ivanova/` | латиница маленькими буквами, цифры, дефис; у каждого свой; **после публикации не менять** - на старый адрес могли дать ссылку |
| `name` | да | ФИО | «Иванова Анна Сергеевна» |
| `position` | да | должность | «Логопед-дефектолог» |
| `short` | нет | одна строка для карточки | «Запуск речи, постановка звуков» |
| `photo` | да | имя файла в `photos/` | после сборки - `<slug>.webp` |
| `description` | да | абзацы для окна и страницы | список строк; строки с «— » - пункты списка; можно `[]` |

## Фото

Подойдет фото с телефона: JPEG или PNG, любого размера. Портрет, лицо в верхней трети
кадра: в карточке фото обрезается в квадрат по лицу.

Фото с iPhone в формате HEIC сборка не читает: перед этим сохраните его как JPEG (на
iPhone: «Настройки» -> «Камера» -> «Форматы» -> «Наиболее совместимый», или отправьте
себе фото в мессенджере и сохраните оттуда).

**Что сделает сборка** (`npm run build`), когда увидит в `photo` не `.webp`:

1. повернет фото, как его снимали;
2. уменьшит до 800 px по длинной стороне;
3. сохранит рядом `ivanova.webp` без метаданных (геометки, модель телефона, дата съемки);
4. впишет в `block.json` новое имя: `"photo": "ivanova.webp"`.

Исходник `ivanova.jpg` останется в папке, но в git не попадет (так настроен
`.gitignore`); сборка напомнит, что его можно удалить.

## Добавить специалиста

1. Назвать фото фамилией латиницей, например `ivanova.jpg`, и положить в
   `site/content/blocks/specialists/photos/`.
2. В `block.json` добавить запись в `items` - туда, где специалист должен стоять в
   карусели, через запятую:

   ```json
   {
       "slug": "ivanova",
       "name": "Иванова Анна Сергеевна",
       "position": "Логопед-дефектолог",
       "short": "Запуск речи, постановка звуков",
       "photo": "ivanova.jpg",
       "description": [
           "Первый абзац о специалисте.",
           "Направления работы:",
           "— запуск речи;",
           "— постановка звуков."
       ]
   }
   ```

3. Из папки `site/` запустить `npm run build`. Сборка обработает фото, поправит
   `photo`, проверит запись и соберет сайт.
4. Посмотреть: `npm run dev`, затем http://localhost:4321/#specialists и
   http://localhost:4321/specialisty/ivanova/.

Однофамильцы - `slug` с первой буквой имени: `ivanova-a`, `ivanova-m`.

## Изменить

- **Текст** (должность, «кратко», описание) - поправить поле.
- **Фото** - положить новый файл (например `ivanova.jpg`) и вписать его имя в `photo`;
  сборка заменит старый `ivanova.webp`.
- **ФИО** - `name`; `slug` не трогать, даже если сменилась фамилия.

## Убрать специалиста

1. Удалить его запись `{ ... }` из `items` вместе с запятой.
2. Удалить фото из git (из корня репозитория):

   ```bash
   git rm site/content/blocks/specialists/photos/ivanova.webp
   ```

Его страница `/specialisty/ivanova/` исчезнет при следующей публикации.

## Переставить

Порядок в карусели - порядок записей в `items`.

## Частые ошибки

| Сообщение | Что не так |
|---|---|
| `items.18.photo: нет файла photos/ivanova.webp` | файла нет или опечатка в имени |
| `photos/ivanova.jpg: фото не обработано ... запустите npm run build у себя` | фото отправили в репозиторий без сборки (так пишет хук при коммите и сервер) |
| `формат HEIC ... не читается` | сохраните фото как JPEG |
| `items.5.slug: адрес ivanova уже занят` | два специалиста с одним `slug` |
| `slug: только латиница, цифры и дефис` | в `slug` русские буквы, пробел или заглавные |

## Для нейросети

> Правь только `site/content/blocks/specialists/block.json` по
> `docs/content/specialists.md`. `slug` - фамилия латиницей маленькими буквами, у каждого
> свой; у существующих специалистов `slug` не меняй. В `photo` - имя файла, который
> пользователь положил в `photos/`; фото не конвертируй сам - это сделает `npm run build`.
> Порядок в карусели - порядок в `items`. Файлы не удаляй: дай команду `git rm`. После
> правки запусти `npm run build` в `site/` и исправь ошибки по их тексту.
