# Контракт `news.json`

Что воркер отдает сборке сайта. Пишет - `pipeline/src/pipeline/export/news.py`
(`build_news`, `write_news`), читает - сайт при сборке (путь в `NEWS_JSON`).
Меняется только вместе с `version` и обеими сторонами в одном коммите.

Файл лежит в `<DOBROMIR_DATA>/export/news.json`, пишется атомарно (временный
файл и `os.replace`), так что сборка никогда не видит его недописанным.

## Верхний уровень

| Поле | Тип | Что |
|---|---|---|
| `version` | число | версия формата, сейчас `1` |
| `generated_at` | строка ISO 8601 с поясом | когда записан; при сравнении «изменился ли файл» не учитывается |
| `posts` | массив | живые (не удаленные) посты, новые первыми по дате публикации |

## Пост

| Поле | Тип | Что |
|---|---|---|
| `id` | число | id поста в VK, уникален внутри группы |
| `slug` | строка | `ГГГГ-ММ-ДД-vk<id>`, дата по Симферополю; для адреса страницы, не меняется при правке |
| `title` | строка | первая непустая строка текста, до 120 символов с обрезкой по слову и «…». **Может быть пустой** (пост только с фото) - сайт подставляет запасной заголовок |
| `date` | строка ISO 8601 | публикация, `+03:00` (Europe/Simferopol) |
| `edited_date` | строка ISO 8601 или `null` | последняя правка в VK; `null`, если не правили или правка в ту же минуту. «Обновлено ...» показывать, только если дата (день) отличается от `date` |
| `pinned` | логическое | закреплен в VK |
| `tags` | массив строк | хэштеги без `#`, без повторов, в порядке появления |
| `source_url` | строка | пост в VK; на него же ведут ссылки на документы и видео |
| `text` | строка | текст поста **как есть**: не экранирован, разметка VK (`[club1\|имя]`, ссылки) не преобразована - это задача сайта (экранирование, XSS) |
| `photos` | массив | см. ниже; только скачанные фото |
| `links` | массив `{url, title}` | вложения-ссылки |
| `media` | массив `{kind, title}` | документы и видео: `kind` - `doc` или `video`. Файлов нет, на сайте - ссылка на `source_url` |
| `repost` | объект или `null` | оригинал, если пост - репост |

Опросы и прочие вложения в экспорт не попадают.

## Фото

| Поле | Тип | Что |
|---|---|---|
| `file` | строка | путь относительно каталога `media/`, например `photos/m242263522_457239030.jpg` |
| `width`, `height` | числа | размеры файла после поворота по EXIF |

Файлы лежат в `<SITE_ROOT>/media/`, метаданные EXIF/GPS вычищены, разрешение
исходное (то, что отдал VK). Порядок важен: первое фото - обложка. Фото, которое
еще не скачано, в экспорт не попадает и появится после следующего скачивания.

## Репост

| Поле | Тип | Что |
|---|---|---|
| `source_name` | строка или `null` | имя группы или человека; `null`, если VK его не отдал |
| `source_url` | строка | оригинал в VK |
| `date` | строка ISO 8601 | публикация оригинала |
| `text`, `photos`, `links`, `media` | | как у поста |

Если у самого репоста нет текста, `title` и `tags` поста взяты из оригинала.

## Пример

```json
{
  "version": 1,
  "generated_at": "2026-10-23T01:09:14+03:00",
  "posts": [
    {
      "id": 18,
      "slug": "2026-10-22-vk18",
      "title": "Фотоотчет с занятия клуба юных полярников",
      "date": "2026-10-22T23:37:22+03:00",
      "edited_date": null,
      "pinned": false,
      "tags": [],
      "source_url": "https://vk.com/wall-242263522_18",
      "text": "Фотоотчет с занятия клуба юных полярников...",
      "photos": [{"file": "photos/m242263522_457239030.jpg", "width": 900, "height": 900}],
      "links": [],
      "media": [],
      "repost": null
    }
  ]
}
```
