## Резюме

Разработан полный цикл деплоя: bootstrap.sh (первичная подготовка), deploy.sh (обновление из main), run-worker.sh (для cron), backup-db.sh (бэкап SQLite), locked.py (блокировка воркера). Cron: `17 * * * *` (воркер), `47 * * * *` (deploy). Бэкапы: 7 последних копий SQLite. Воркер: блокировка fcntl, коды выхода 0/1/2/3, status.json, лог с ротацией. Тесты: 217 passed (pipeline), 28 passed (site).

## Деплой

### Скрипты (deploy/)
- **bootstrap.sh** — первичная подготовка (без `--apply` только проверяет). Проверяет Python >= 3.10, Node >= 22, каталог данных вне клона. Создаёт каталоги, `.env` из шаблона (права 600), uv в свой venv, npm ci, пробная сборка.
- **deploy.sh** — обновление из `main` (руками или `--cron`). Шаги: git fetch, ff (только вперед), зависимости, пробная сборка, копия базы, миграции, включение. При ошибке — откат кода до миграций, письмо.
- **run-worker.sh** — для cron. Задает PATH, читает .env, вызывает воркер, пробрасывает код выхода. При успехе молчит.
- **backup-db.sh** — бэкап SQLite (встроенный `.backup`), 7 копий, права 600.
- **locked.py** — запуск под блокировкой воркера (`DOBROMIR_LOCK_HELD=1`).
- **crontab.example** — строки для панели CronTab.
- **htaccess.example** — шаблон .htaccess (301, кэш, сжатие, noindex для staging).

### Cron
- `17 * * * *` — воркер (run-worker.sh)
- `47 * * * *` — deploy.sh --cron
- Бэкап БД раз в сутки

### Обновление (пересмотрено 2026-10-28)
- Сервер на `main`, обновление руками или cron `--cron`
- Весь деплой под блокировкой воркера
- При ошибке — прежний релиз, откат кода до миграций, письмо
- Упавший коммит — в `<данные>/deploy-state`, cron его не повторяет
- Успех — письмо «Сайт обновлен» со списком коммитов
- `--to <коммит>` — откат кода

## Воркер

### Точка входа
`python -m pipeline worker`

### Блокировка
`fcntl.lockf` на `<данные>/worker.lock`. Второй запуск при занятой блокировке — код 0, строка в логе (не ошибка).

### Коды выхода
- 0 — успех или нет изменений
- 1 — прочая ошибка
- 2 — ошибка токена VK
- 3 — сработала защита от массового удаления

### status.json
Атомарная запись, без секретов: `last_ok_poll_at, last_build_at, posts_total, posts_deleted, errors[], builds_today, pending, worker_version`

### Лог
`logs/worker.log`, ротация 5 x 1 МБ, только в файл. При успехе вывода нет.

### Сообщения для писем
1-2 строки по-русски в stderr. Ключи вычищаются из текста.

## Сборка релиза

- Сборка в `releases/<ts>/` с окружением с нуля (ключей VK нет)
- Ссылка `media` на общий каталог
- Проверки: `index.html`, sitemap, `media`, страниц не меньше на max(3, 20%)
- Переключение: `os.symlink` + `os.replace`
- Чистка: 5 последних и текущий, только каталоги с именем-временем
- Откат: `python -m pipeline rollback [--to]`
- Таймаут сборки: 10 минут (по умолчанию)
- При ошибке: релизная папка удаляется, `public_html` не трогается, `pending` остается

## Чистка медиа

- Удаляет фото, на которое не ссылается ни один пост в базе
- Защиты: фото живого поста не удаляется; удаляется только `photos/<uid>.jpg` внутри `media/`; сначала стирается запись, потом файл
- Запуск: воркер раз в сутки после полной сверки (если сайт не устарел); вручную: `python -m pipeline media-cleanup [--dry-run]`

## Нюансы эксплуатации

- `SITE_ENV` без дефолта — ошибка в любую сторону вредна
- `SITE_ROOT` должен быть абсолютным путем (без `~`)
- `NEWS_RETENTION_DAYS` по умолчанию 90
- `MAX_BUILDS_PER_DAY` = 4
- Логи: RotatingFileHandler, 5 x 1 МБ, только в файл
- При успехе воркер выводит 0 байт (cron шлет письмо на любой вывод)
- Ключи вычищаются из текста ошибок
- `public_html` — обычный каталог (старый сайт) — deploy.sh отказывает до сборки
- Бэкап БД: встроенный `sqlite3 .backup`, проверяется `integrity_check`, права 600
- Воркер не удаляет файлы и не трогает `.env`
- Deploy не трогает `bprof.a978879k.beget.tech`
- `git fetch` только вперед (ff, без слияний)
- Правки в клоне или переписанная история — отказ
- Упавший коммит — в `<данные>/deploy-state`
- `--cron` молчит без нового коммита
- `--to <коммит>` — откат кода, cron ждет запуска без `--to`
- Весь деплой под блокировкой воркера
- До миграций: откат кода и зависимостей
- После начала миграций: код остается новым
