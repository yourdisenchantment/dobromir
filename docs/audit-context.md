# Аудит кода: контекст для проверки безопасности

Для кого: модель безопасности (Claude, GPT и др.), которая проверяет код на уязвимости.
После проверки — вернуть фидбэк, я исправлю.

## Общая информация

- **Проект:** статичный сайт центра коррекционной педагогики «Добромир» (Симферополь)
- **Стек:** Astro (фронтенд) + Python 3.10 (бэкенд/воркер) + SQLite
- **Хостинг:** Beget Blog (shared), cron раз в час
- **Данные:** новости из VK-паблика, фото детей (материалы о детях)
- **Репозиторий:** приватный на GitVerse

## 1. XSS (межсайтовый скриптинг)

### Контекст
Сайт показывает текст постов из VK. Посты могут содержать произвольный текст, включая HTML-теги, ссылки, хэштеги. Текст разбирается в `pipeline/parse/posts.py` и экспортируется в `news.json`. Сайт читает `news.json` и выводит текст через Astro-компоненты.

### Что проверять
- `site/src/lib/vktext.ts` — функция `parseVkText()`, `safeHref()`. Как экранируется текст? Какие протоколы разрешены в ссылках?
- `site/src/components/PostText.astro` — вывод текста. Используется ли `set:html` или обычный вывод?
- `site/src/components/PostContent.astro` — вывод ссылок-вложений. Проверяется ли схема URL?
- `pipeline/src/pipeline/parse/posts.py` — функция `make_title()` и обработка текста. Экранируется ли HTML?
- `pipeline/src/pipeline/export/news.py` — как текст экспортируется в JSON. Есть ли экранирование?

### Известные меры
- Astro экранирует текст по умолчанию
- `safeHref()` проверяет протокол (только http/https)
- Ссылки-вложения фильтруются через `safeHref()` (добавлено 2026-10-27)
- JSON-LD использует `JSON.stringify()` (безопасно)

### Что искать
- Места, где `set:html` используется с неэкранированными данными
- Места, где HTML из поста VK выводится напрямую
- Обход `safeHref()` (например, через `data:` или `javascript:` в других местах)
- XSS через атрибуты (alt, title, href)

## 2. SQL-инъекции

### Контекст
SQLite-база хранит посты, фото, метаданные. Все запросы через `sqlite3` с параметризованными запросами (`?`).

### Что проверять
- `pipeline/src/pipeline/store/state.py` — все методы `Store` (upsert, mark_deleted, expire_posts, etc.)
- `pipeline/src/pipeline/store/db.py` — миграции (`_statements()` разбивает SQL по `;`)
- Проверить: нет ли f-строк или конкатенации в SQL-запросах
- Проверить: миграции не содержат пользовательский ввод

### Известные меры
- Все запросы через `?` параметры
- Миграции разбиваются по `;` (нет пользовательского ввода)

### Что искать
- Динамическое формирование SQL (f-strings, format, concatenation)
- `executescript()` с пользовательским вводом
- Миграции, которые могут быть изменены злоумышленником

## 3. Утечка секретов

### Контекст
Ключи VK (`VK_SERVICE_TOKEN`, `VK_COMMUNITY_TOKEN`) хранятся в `~/dobromir-data/.env` (права 600). Пайплайн читает их через `settings.py`. Ключи не должны попадать в логи, статус, трейсбеки, репозиторий.

### Что проверять
- `pipeline/src/pipeline/settings.py` — `VkSettings` с `repr=False`, `_scrub()` в worker
- `pipeline/src/pipeline/worker.py` — `_scrub()` вычищает ключи из текста ошибок
- `pipeline/src/pipeline/vk/client.py` — ключ не попадает в текст исключений
- `.gitignore` — закрывает `.env`, базу, данные
- Логи воркера — не содержат ключей
- `status.json` — не содержит ключей

### Известные меры
- `field(repr=False)` для токенов
- `_scrub()` в worker
- VkError не включает ключ в сообщение
- `.gitignore` закрывает `.env`

### Что искать
- Ключи в логах, трейсбеках, статусе
- Ключи в URL (query params вместо headers)
- Ключи в git-истории
- Ключи в `repr()` или `str()` объектов
- Ключи в сообщениях об ошибках

## 4. Путь-траверсал (path traversal)

### Контекст
Сайт раздает фото из `MEDIA_DIR` через dev-сервер. На хостинге фото лежат в `media/photos/`. Воркер скачивает фото и сохраняет в `media/photos/<uid>.webp`.

### Что проверять
- `site/astro.config.mjs` — функция `devMedia()` (раздача `/media/`)
- `pipeline/src/pipeline/media/photos.py` — `fetch_photo()`, сохранение файлов
- Проверить: нет ли возможности выйти за пределы каталога через `../` в URL
- Проверить: валидация имени файла (только `.webp`)

### Известные меры
- `devMedia()` проверяет `file.startsWith(root + sep)` и `file.endsWith(".webp")`
- Фото сохраняются с именами из VK (uid), не из пользовательского ввода

### Что искать
- Обход проверки `startsWith` (например, через symlink)
- Загрузка файлов с произвольными именами
- Чтение файлов вне каталога media

## 5. Инъекция команд (command injection)

### Контекст
Воркер запускает `npm run build` через `subprocess.run()` с списком аргументов (не shell=True). Deploy-скрипты на bash.

### Что проверять
- `pipeline/src/pipeline/release.py` — `subprocess.run()` с `cmd` списком
- `deploy/*.sh` — использование переменных в командах
- Проверить: нет ли `shell=True` или конкатенации команд

### Известные меры
- `subprocess.run(cmd, ...)` где `cmd` — список строк
- `shell=False` по умолчанию
- Bash-скрипты используют `set -euo pipefail`

### Что искать
- `shell=True` в subprocess
- Конкатенация строк в команды
- Переменные без кавычек в bash
- Инъекция через имена файлов или путей

## 6. SSRF (Server-Side Request Forgery)

### Контекст
Воркер делает HTTP-запросы к VK API и скачивает фото по URL из ответа VK.

### Что проверять
- `pipeline/src/pipeline/vk/client.py` — `call()` использует `self._vk.api_url`
- `pipeline/src/pipeline/media/photos.py` — `fetch_photo()` скачивает по `photo.url`
- Проверить: можно ли подменить URL для скачивания произвольного файла

### Известные меры
- URL фото берется из ответа VK (доверенный источник)
- `photo.url` не из пользовательского ввода

### Что искать
- Возможность подмены URL через VK-пост
- Доступ к внутренним адресам (localhost, 169.254.x.x)
- Отсутствие валидации URL перед скачиванием

## 7. Обработка ошибок и отказоустойчивость

### Контекст
Воркер должен корректно обрабатывать ошибки VK, сети, файловой системы. При сбое сайт должен продолжать работать на предыдущей версии.

### Что проверять
- `pipeline/src/pipeline/worker.py` — `run_worker()` ловит все исключения
- `pipeline/src/pipeline/release.py` — при ошибке сборки релиз удаляется, `public_html` не трогается
- `pipeline/src/pipeline/reconcile.py` — `classify_missing()` не считает ошибку VK удалением
- Проверить: нет ли состояний, при которых база или файлы могут быть повреждены

### Известные меры
- `try/except` вокруг всего запуска воркера
- Атомарная запись `status.json` (через `.tmp` + `os.replace`)
- Релиз собирается в отдельную папку, переключение атомарно
- SQLite в режиме WAL (если включен)

### Что искать
- Race conditions при параллельном доступе к базе
- Неполная запись файлов (crash во время записи)
- Утечка ресурсов (файловые дескрипторы, соединения)
- Некорректное состояние при частичном сбое

## 8. Логика удаления и восстановления

### Контекст
Посты удаляются мягко (`deleted_at`). При восстановлении в VK пометка снимается. Защита от массового удаления: если > max(3, 20%) постов к удалению — не применять.

### Что проверять
- `pipeline/src/pipeline/reconcile.py` — `classify_missing()`, `reconcile_window()`, `full_reconcile()`
- `pipeline/src/pipeline/store/state.py` — `mark_deleted()`, `upsert()` (восстановление)
- Проверить: можно ли обойти защиту от массового удаления

### Известные меры
- `classify_missing()` — единственная функция, решающая «удален или не знаем»
- Пустой ответ VK не считается удалением
- Ошибка VK/сети/токена не считается удалением
- Защита: `max(3, 20% неудаленных постов)`

### Что искать
- Обход защиты через частичные ответы
- Ложные удаления при сбоях сети
- Восстановление удаленного поста (пометка снимается)
- Физическое удаление постов старше срока хранения

## 9. Обработка фото и медиа

### Контекст
Фото скачиваются из VK, конвертируются в WebP (1600 + 800 px), сохраняются в `media/photos/`. Чистка удаляет фото без ссылок из базы.

### Что проверять
- `pipeline/src/pipeline/media/photos.py` — `fetch_photo()`, `render()`, `save_photo()`
- `pipeline/src/pipeline/media/cleanup.py` — `cleanup_media()`
- Проверить: можно ли загрузить произвольный файл через VK-пост
- Проверить: защита от path traversal в именах файлов

### Известные меры
- Имена файлов из VK (uid), не из пользовательского ввода
- Чистка: только `photos/<uid>.webp` внутри `media/`
- Сначала стирается запись, потом файл
- Фото живого поста не удаляется

### Что искать
- Загрузка произвольных файлов через VK
- Обход проверки расширения файла
- Удаление файлов вне `media/photos/`

## 11. Зависимости и supply chain

### Контекст
- Python: uv + pyproject.toml (без границ версий), uv.lock фиксирует
- Node: npm + package.json (latest для всего, кроме TypeScript 6), package-lock.json фиксирует
- На сервере: uv sync --frozen, npm ci

### Что проверять
- `pipeline/pyproject.toml` — зависимости без границ
- `site/package.json` — `latest` для всех, кроме TypeScript
- `pipeline/requirements.txt` — генерируется из uv.lock
- Проверить: известные уязвимости в зависимостях

### Известные меры
- Lock-файлы фиксируют точные версии
- `npm ci` и `uv sync --frozen` воспроизводимы
- TypeScript закреплен на 6 (исключение)
- `eslint-plugin-jsx-a11y` имеет override для ESLint 10

### Что искать
- Уязвимости в зависимостях (npm audit, pip audit)
- Устаревшие зависимости с известными CVE
- Лицензионные проблемы

Shared-хостинг Beget Blog. Правила: демоны запрещены, 80 CP/сутки, 30 процессов на домен. SSH включен. Cron настраивается в панели.

### Что проверять
- Доступность `api.vk.ru` с хостинга
- Доступность `gitverse.ru` с хостинга
- CP на сборку (3 сборки подряд)
- `venv`/`pip` в cron
- `public_html` как симлинк
- `.htaccess` с 301 и кириллицей
- SSL и автопродление

### Известные меры
- Проверки описаны в `docs/vk-check-scenario.md`
- Bootstrap.sh проверяет окружение
- Deploy.sh имеет откат при ошибке

### Что искать
- Недоступность внешних сервисов с хостинга
- Превышение лимитов CP
- Проблемы с правами файлов
- Проблемы с cron и окружением
