# Инструкция для нейросети: как работать с содержимым сайта «Добромир»

> Этот файл — единая инструкция для нейросети (Claude, ChatGPT и др.), которая правит
> содержимое сайта. Дай ей этот файл и документ нужного раздела из `docs/content/`.
> Правила здесь сильнее любых умолчаний.

## Что можно менять

**Только файлы в `site/content/`:**
- `site/content/page.json` — порядок разделов и меню
- `site/content/blocks/<раздел>/block.json` — содержимое раздела
- `site/content/blocks/specialists/photos/` — фото специалистов (только класть файлы, не удалять)

**Не трогать:**
- Всё вне `site/content/` (код, стили, скрипты, конфиги)
- Поле `type` у раздела (вид раздела меняет разработчик)
- `slug` у специалиста после публикации (на старый адрес могли дать ссылку)
- Файлы не удалять — дать список и команду `git rm`, пользователь выполнит сам

## Как править

1. **Открыть `block.json` нужного раздела** и поменять текст по документу раздела.
2. **Фото** — положить файл в `photos/` (JPEG/PNG/любой формат, кроме HEIC — его сначала в JPEG). Имя — фамилия латиницей: `ivanova.jpg`. В `photo` вписать имя файла.
3. **Собрать** из папки `site/`:

   ```bash
   npm run build
   ```

4. **Проверить** — ошибки появятся по-русски с указанием файла и поля.
5. **Отправить** в GitVerse: `git add`, `git commit`, `git push`.

## Правила JSON

- Текст — в прямых кавычках `"..."`. Кавычки внутри текста — «елочки» или `\"`.
- Между записями списка и между полями — запятая; после последней — нет.
- Число без кавычек (`"count": 12`), цифра для показа — в кавычках (`"value": "250+"`).
- Удалили запись — проверьте запятые до и после нее.

## Что сборка делает сама

| Что | Как |
|-----|-----|
| Фото | Поворот по EXIF, уменьшение до 800 px, WebP без метаданных, имя в block.json |
| Текст | Лишние пробелы, тире «—», кавычки «елочки» |
| Проверка | Схема zod: типы, обязательные поля, наличие файлов фото |
| Ошибки | По-русски, с указанием файла и поля |

## Что сборка НЕ делает

- Не меняет `type` блока
- Не добавляет новые поля (они не пройдут схему)
- Не удаляет файлы (только предупреждает о неиспользуемых)
- На сервере/в хуке: только проверка, не меняет файлы

## Как добавить специалиста

1. Назвать фото фамилией латиницей: `ivanova.jpg`
2. Положить в `site/content/blocks/specialists/photos/`
3. В `block.json` добавить запись в `items`:

```json
{
    "slug": "ivanova",
    "name": "Иванова Анна Сергеевна",
    "position": "Логопед-дефектолог",
    "short": "Запуск речи, постановка звуков",
    "photo": "ivanova.jpg",
    "description": [
        "Первый абзац о специалисте.",
        "Направления работы:",
        "— запуск речи;",
        "— постановка звуков."
    ]
}
```

4. Запустить `npm run build` — фото обработается автоматически
5. Проверить: `npm run dev` -> http://localhost:4321/

**Однофамильцы:** `slug` с первой буквой имени: `ivanova-a`, `ivanova-m`

## Как добавить карточку (услуга, направление)

В `items` нужного блока, через запятую:

```json
{
    "title": "Название",
    "text": "Описание в два-три предложения."
}
```

С подзаголовком и списком:

```json
{
    "title": "Название",
    "subtitle": "от 5 лет",
    "text": "Описание.",
    "list": ["пункт 1", "пункт 2"]
}
```

## Как добавить отзыв

В `items` блока `reviews`:

```json
{
    "text": "Текст отзыва.",
    "author": "Мама воспитанника"
}
```

**Личные данные:** не оставлять имен, фамилий и диагнозов детей. Автор — обезличенно.

## Как добавить цифру

В `items` блока `facts`:

```json
{ "icon": "school", "value": "15", "label": "лет работы" }
```

Чужая цифра — с источником:

```json
{
    "icon": "diversity_3",
    "value": "1500",
    "label": "детей с аутизмом в Крыму",
    "source": { "title": "Минздрав РК, 2024", "url": "https://..." }
}
```

Значки: `accessibility_new`, `calendar_month`, `child_care`, `diversity_3`, `family_restroom`,
`favorite`, `fingerprint`, `groups`, `health_and_safety`, `location_on`, `meeting_room`,
`neurology`, `psychology`, `record_voice_over`, `school`, `sentiment_satisfied`,
`stethoscope`, `volunteer_activism`

## Как изменить контакты

Телефон записи — первый в `phones`. При смене телефона записи:
1. Поменять `number` у первой записи в `phones`
2. Поменять `href` первой кнопки в `hero` (`tel:` и цифры без пробелов)

Адрес, карта, ссылка на VK — в соответствующих полях.

## Как переставить разделы

В `site/content/page.json` — поменять порядок имен в списке `blocks`. Меню перестроится
автоматически (по полю `menu` в `block.json`).

## Как убрать раздел

Удалить имя из `page.json`. Папку можно не трогать — вернуть раздел значит вписать
имя обратно. Нельзя убрать `contacts` (из него берут телефон) и не стоит убирать `hero`
(главный заголовок страницы).

## Частые ошибки

| Сообщение | Причина |
|-----------|---------|
| `JSON не читается` | Лишняя/пропущенная запятая, незакрытая кавычка |
| `items.1.label: пусто` | Пустое обязательное поле |
| `нет файла photos/ivanova.webp` | Файл не найден или опечатка в имени |
| `фото не обработано` | Запустите `npm run build` у себя |
| `лишнее поле description` | Нет такого поля, есть `text` |
| `slug: адрес уже занят` | Два специалиста с одним slug |
| `menu: не длиннее 20 знаков` | Слишком длинный пункт меню |
| `blocks: блок указан дважды` | Одно имя дважды в page.json |

## Правила безопасности

- **Личные данные:** не оставлять имен, фамилий и диагнозов детей в отзывах
- **Согласие:** отзыв из VK или переписки — с согласия написавшего
- **Фото:** только с согласия (решение от 2026-10-19)
- **Секреты:** не класть в репозиторий (ключи VK, токены)

## После правки

1. `npm run build` в `site/` — сборка проверит и доведет содержимое
2. `npm run dev` — посмотреть глазами (http://localhost:4321/)
3. `git add`, `git commit`, `git push` — отправить в GitVerse
4. На сервере сайт обновится автоматически (cron, раз в час)

## Подсказка для нейросети

> Правь только файлы в `site/content/` по `docs/HOWTO-add-content.md` и документу
> раздела из `docs/content/`. Не меняй поле `type`, не трогай файлы вне `site/content/`,
> не придумывай новых полей — их нет в таблицах, и сборка их не пропустит. Тексты — на
> русском, кавычки «елочки», тире «—». Фото не конвертируй сам: положи файл в `photos/`
> и впиши имя в `photo` — это доделает `npm run build`. После правки запусти
> `npm run build` в `site/` и исправь ошибки по их тексту. Ничего не удаляй сам: дай
> список файлов и команду `git rm`. Не меняй `slug` у существующих специалистов.
